# Typora Web Styler

将 **Typora 主题应用到当前网页正文**的 Chrome / Edge 扩展。直接改变原文章的排版，保留页面布局、标题锚点和交互，无需获取作者的 Markdown 文件。

- 自动转换 Typora CSS，支持导入本地字体和可选背景图片。
- 所有主题共用配置，可保留原标题、字体、行距和代码配色。
- 识别正文、切换主题、一键恢复原样。
- 查看导入、转换、识别和应用日志，支持筛选与导出。

## 环境与快速开始

当前版本 **0.2.0**。构建需要 **Node.js 20+、pnpm 12**（也支持 npm）；优先支持 Windows 上的 Chrome / Edge / 大部分浏览器，PowerShell 即可。

```powershell
pnpm install --frozen-lockfile
pnpm run build
```

使用 npm 也可以：`npm ci --cache .cache/npm`，然后 `npm run build`。

1. 打开 `edge://extensions` 或 `chrome://extensions`，启用开发人员模式，加载项目的 **`dist/`** 目录。
2. 打开博客，点击扩展图标，选择“纸笺 · 测试主题” → 识别正文 → 确认范围 → 应用主题。
3. 从弹窗底部进入设置页，导入自己的 CSS、调整统一配置或查看日志；需要撤销时点击“恢复原样”。

已有 `dist/` 时可直接安装。源码更新后重新构建、重新加载扩展，并刷新博客标签页。

## 正文识别与更新

“正文区域”填写 CSS 选择器，例如 `.post-content`，不是 URL 或 Markdown 文件路径。留空会尝试已验证的站点规则及 `article/main/[role=main]`；匹配不明确时需手动指定唯一正文容器。Saurlax 的人工智能基础文章已验证为 `article#article-content`。高亮是整个容器边缘约 1.8 秒的紫色轮廓，长文章可能不容易看清。

切换主题时重新识别、确认，再应用所选主题。更新插件后刷新网页，可清理旧版页面控制器；已导入主题保留，0.2 能读取 0.1 的主题记录。主题管理页与弹窗采用暖白、浅绿的圆润界面；配套资源在导入区的折叠项中，统一配置按正文排版、代码阅读、字体与背景分组。

## 导入自己的主题与资源

打开弹窗底部的“主题、统一配置与日志”，进入设置页：

1. 选择 Typora 的主 `.css` 文件，最多 **1 MB（1,048,576 字节）**。
2. 主题名称可自定义；留空使用 CSS 文件名。
3. 需要自定义字体或背景图片时，补选配套资源文件，或选择包含主 CSS 和资源的主题目录。目录保留相对路径，适合主题引用 `fonts/xxx.woff2` 等文件。
4. 点击“分析并导入”，查看转换报告；回到博客选主题并应用。

字体支持 WOFF、WOFF2、TTF、OTF；图片支持 PNG、JPEG、WebP、GIF。最多 64 个配套资源，单文件最多 16 MB，合计最多 24 MB。目录里的其他 CSS 不会自动合并，`@import` 和远程 URL 不自动加载。选散文件时可以按唯一文件名匹配，匹配警告会进入报告；同名文件不唯一时需使用正确目录结构。

字体在网页中以独立名称加载，切换/恢复会释放扩展添加的字体。背景图片默认关闭，需要在统一配置中开启；正文容器背景还需要单独开启“允许替换正文容器背景”。图片可能被网页 CSP 限制，失败会记录日志并继续使用可用样式。图片资源不包含 SVG。

主题原文和资源保存在扩展本地 IndexedDB；配置、元信息与日志保存在 `chrome.storage.local`。资源只在本机处理，不上传服务器。

## 自己上传的全局背景

设置页下方的“给阅读换一张背景”独立于主题资源。上传一张 PNG / JPEG / WebP / GIF（最多 16 MB），开启背景并保存，返回文章再次应用主题即可。图片居中铺满窗口、保持比例，所有主题共用同一张图片。

- 正文底色不透明度：默认 90%，只改变正文容器底色，不让文字变透明。
- 背景图片不透明度：默认 50%，单独控制图片浓淡。
- 两个滑块均为 0% 完全透明、100% 完全不透明。启用后，正文根背景以全局设置优先；代码块、引用等保留各自背景。
- 切换主题保留这套背景；“恢复原样”撤销当前网页的图片层和底色修改。删除图片或关闭背景后，需要再次应用主题，其他已打开会话不会立即改变。

图片与配置保存在本地 IndexedDB，不上传。自定义图片加载失败会取消本次应用并恢复旧会话。背景层不接收点击；网站外层的不透明容器仍可能遮住图片，第一版不调整这些容器。预览仅示意透明度，实际正文底色来自主题或原站，透明底色使用白色作为回退。带图片时，抽样对比度检查不能保证实际阅读效果。

## 所有主题共用的统一配置

设置页提供以下选项：

| 配置 | 默认 |
| --- | --- |
| 保留原标题字号 / 颜色 | 关闭 |
| 保留原正文字体 / 字号 / 行距 | 关闭 |
| 保留原链接颜色 | 关闭 |
| 保留原代码配色 | 开启 |
| 保留原代码背景色 | 关闭 |
| 加载主题配套的本地字体 | 开启 |
| 允许使用本地背景图片 | 关闭 |
| 允许替换正文容器背景 | 关闭 |

保存后，在网页再次点击“应用主题”生效；已经应用的其他标签页不会立即改变。正文字号保留不包括标题和代码，正文字体/行距保留不包括代码。关闭代码配色保护后，会尝试将常见 Typora CodeMirror 类映射到 Prism/Highlight.js；Shiki 的内联配色等结构仍可能盖过主题。

保留选项捕获应用前的相应样式，用有限的内联声明阻止主题简写和继承间接改变它们；恢复仅撤销扩展仍持有的声明。应用期间网站自身的动态视觉状态未必实时反映，新增节点也不会自动补齐所有保护；需要时重新应用。

## 日志与排错

设置页点击“日志”，可按成功/警告/错误、导入/转换/正文识别/应用与恢复/配置筛选，搜索详细信息，导出 JSON、刷新或清空。

日志记录导入失败、CSS 解析问题、跳过的规则、缺失资源、字体/图片加载结果、正文描述、主题应用与恢复等。仅在本机保存，最多 300 条、约 1.5 MB；不保存完整 CSS、资源数据和文章正文。页面地址省略查询参数与 hash，导出前仍应检查其中的网站路径和主题信息。

主题没变化时先确认正文选择范围，再看转换报告和日志。字体没变化时检查配套文件、字体引用和“保留原正文字体”选项。图片没出现时检查两个背景开关、资源路径和页面 CSP。

## 当前边界

- 主题限定正文，不重建 `body`，不修改原 ID，不重新渲染代码、公式或图表；保护正文内控件、公式和 SVG 等区域。
- 默认保留原站正文宽度、位置和根留白；支持常见文本、块级样式、变量、选择器、`@media/@supports`，将静态 `rem` 基准换算为 px。
- 编辑器界面、动画、伪元素、CSS 规则内嵌套及未知结构保守跳过；不保证任意主题像素级复刻。
- 抽样检查文字对比度，严重降低可读性时取消应用、回退旧主题；背景图片场景不能靠此检查判定可读性。
- 页面路径变化或正文整体替换会结束会话；hash 跳转保留。暂不自动按站点应用，不支持跨域 iframe 或浏览器内部页面。
- 原站高优先级/内联样式仍可能覆盖部分主题，动态页面和更多浏览器需要继续验证。

## 项目结构

采用原生 JavaScript、Manifest V3、PostCSS 及选择器/声明值 AST，使用 esbuild 本地打包，无需服务器或 AI 接口。

| 目录 | 职责 |
| --- | --- |
| `src/theme/` | CSS 转换、主题存储、字体/图片资源及代码结构适配 |
| `src/content/` | 正文识别、样式保护、应用会话和撤销 |
| `src/background/` | 消息、浏览器注入和操作协调 |
| `src/settings/`、`src/diagnostics/` | 全局配置与日志存储 |
| `src/popup/`、`src/options/`、`src/logs/` | 扩展界面 |
| `scripts/`、`tests/` | 构建和行为验证 |

`markdown-viewer/` 是旧项目参考目录，保持独立，不参与新插件构建或 Git 提交。详细模块索引与设计决策见 [AEGNTS.md](AEGNTS.md)。

## 开发、验证与接力

```powershell
pnpm test
pnpm run build
pnpm run test:browser
```

项目通过 `packageManager` 固定 pnpm **12.3.4**，并提供 `pnpm-lock.yaml`；`pnpm-workspace.yaml` 仅包含当前项目，将依赖存储放在 `.cache/pnpm/store`，允许 esbuild 必需的安装脚本。无需手动切换为宽松的依赖提升模式，构建会按实际依赖关系收集第三方许可证。

尚未安装 pnpm 时，参见 [pnpm 官方安装说明](https://pnpm.io/installation)。通过 npm 安装 pnpm 12 需要 Node.js 22.13+；已安装的 pnpm 12 可以用于本项目的 Node.js 20+ 环境。

`package-lock.json` 继续保留，npm 的安装、测试和构建命令仍可使用。修改依赖时同步维护两份锁文件：先用 npm 更新 `package-lock.json`，再执行 `pnpm import` 更新 pnpm 锁文件，最后验证 `pnpm install --frozen-lockfile`。

浏览器验证默认使用本机 Edge 的独立无头配置，包含真实扩展的导入、配置、字体与图片、日志、应用/切换/恢复、交互及 Saurlax 页面检查。自动化仅在独立测试扩展副本添加 localhost/Saurlax 的 host 权限；正式 `dist/manifest.json` 仅声明 `activeTab/scripting/storage`，用户点击工具栏授予访问的流程仍需日常浏览器手测。

测试报告、截图和日志导出保存在 `artifacts/`，构建在 `dist/`，均不提交。不要直接修改生成文件代替源码修复。新的窗口先读 [AGENTS.md](AGENTS.md) 与 [AEGNTS.md](AEGNTS.md)，其中记录模块职责、旧项目复用参考、验证范围和后续计划。
