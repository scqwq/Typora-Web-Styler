# Web-markdown

在当前博客正文上应用 Typora CSS 主题，保留原 DOM、页面布局和标题锚点，支持主题导入、切换与恢复。

当前版本：**0.1.0，第一版原型**。外层目录暂不改名；内层 `markdown-viewer/` 仅供参考，不参与构建。

## 安装与试用

已经构建的扩展位于项目的 `dist/`，浏览器加载的是这个目录，而不是项目根目录。

1. Edge 打开 `edge://extensions`（Chrome 使用 `chrome://extensions`）。
2. 开启开发人员模式，点击“加载解压缩的扩展”。
3. 选择 `D:\moresoftware\markdown-viewer\dist`。
4. 打开博客文章，点击 Web-markdown 扩展图标。
5. 选择“纸笺 · 测试主题”，点击“识别正文”。查看网页短暂高亮的范围，勾选确认后应用。
6. 若识别失败，填写正文容器的 CSS 选择器（例如经检查确认的 `article` 或 `.post-content`），再识别。Saurlax 的人工智能基础文章已实测为 `article#article-content`，并有内置适配。
7. 要切换主题，重新打开弹窗并识别/确认正文，然后选择其他主题应用；点击“恢复原样”撤销。

在扩展弹窗中点击“导入与管理主题”，选择一个 Typora `.css` 文件、填写名称并导入。CSS 会在本地分析；导入界面和应用后都可以查看转换报告。最多保存 20 个自定义主题，每个文件最多 512 KB。

内置主题是专为验证流程编写的测试 CSS，不代表用户真实 Typora 主题已通过验收。

也提供 `web-markdown-0.1.0.zip` 本地分发包。解压后，在扩展管理页选择包含 manifest.json 的解压目录即可；ZIP 本身不能通过“加载解压缩的扩展”直接加载。

## 自动转换的范围

- 将 `#write`、简单 `html/body/:root` 规则映射到正文，不改原节点 ID。
- 常见标题、段落、引用、列表、表格和代码外观规则限定正文范围。
- 支持常见选择器列表、组合器、`:is/:where/:not`、`@media/@supports`。
- 使用会话专用 CSS 变量名，避免覆盖网站自己的布局变量。
- 将主题中的 `rem` 按明确基准换算成 px。顶层静态 html 字号可作为基准；否则使用 16px。复杂动态根字号未完整支持。
- 默认保护正文根的背景、宽度、留白及布局；标题等文本样式尽可能按主题替换。
- 抽样检查正文对比度：如果替换后文字几乎与背景同色，会取消应用并恢复上一状态。它不替代完整视觉验收，背景图片等情况暂不判断。
- 窗口布局、Typora 编辑控件、伪元素、复杂根选择器、动画、自定义字体定义与未知 at-rule 暂时跳过，并记录报告。
- 不自动加载任何主题资源。URL、相对路径资源、`@import` 等依赖不会直接发送网络请求。

## 当前限制

- 不保证所有网站/主题像素级一致。原站内联样式和高优先级规则可能仍覆盖部分主题声明。
- 只操作主框架；浏览器内部页面、扩展商店和跨域 iframe 暂不支持。
- 自动正文候选目前只检查 `article/main/[role=main]`；范围不清晰时要求明确选择器。禁止整页 body 作为正文。
- 保留现有代码 token 配色、公式、SVG/图表和控件。不重复执行高亮、公式或图表渲染。
- 受保护区域会记录一组继承排版属性，以减轻主题影响；会话期间网站自行改变这些继承属性不一定即时反映，恢复后撤销保护。网站新增复杂控件尚不自动重新分类。
- 页面路径变化或正文整体被替换后结束主题会话，需要重新识别；hash 跳转不会结束会话。
- 保留标题字号/颜色/正文字体等独立开关尚未实现。
- 不导出或修改作者的 `.md` 原文件，也不包含旧扩展的 Markdown 原文查看功能。

## 开发与验证

需要 Node.js 20+ 和 npm。Windows PowerShell 可直接运行：

```powershell
npm ci --cache .cache/npm
npm test
npm run build
npm run test:browser
```

构建由 esbuild 输出本地脚本到 `dist/`，不需要 WSL。源码入口为 `src/manifest.json`，修改后重新构建并在扩展管理页重新加载。

浏览器验证默认使用本机 Edge 的独立无头测试配置，测试真实扩展的导入、注入、切换、恢复和页面交互。自动化环境使用单独复制的测试扩展，并添加仅供测试的本地/目标站点 host 权限，因为脚本无法模拟用户点击浏览器扩展按钮授予 activeTab。**正式 dist 仅声明 activeTab、scripting、storage，不含这些测试 host 权限。**

测试报告与应用前后截图输出到 `artifacts/`（不入 Git）。真实目标页的网络访问结果和页面验证结果单独记录，不把夹具通过当成真实主题验收。浏览器工具不可用时，可以先运行转换测试和构建。
